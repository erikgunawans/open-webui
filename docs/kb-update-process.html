Never add a file to the JUP Strategy KB by hand in the app. The sync deletes every file in that collection that it did not put there itself, so a hand-added file disappears on the next run. Nothing warns you when it does. A staff document goes through Route B instead.

Route A: change the Strategy KB

The Strategy KB is generated. You edit the source in ~/jup, never the copy in the app. It holds every kb/*.md except kb/CONTEXT.md (the assistant's operating contract), plus DECISIONS.md and every records/**/*.md.

  1. Edit the source in ~/jup

    • Partner state lives in records/engagements/, not in kb/partners.md. Its state table is generated from the records.
    • Never edit inside a <!-- BEGIN generated:... --> region.
    • Do not use a stage-ladder label as a table cell outside a generated region. Prose that names a stage is fine.
    • kb/gas.md and kb/governance.md are checked: the "5 mmscfd allocation is not secured" caveat must stay true to the G1 gate assessments. Contradicting it fails, and so does deleting it.

  2. Regenerate and check

    From ~/ent-os-new-jup. Exit 0 is clean, 1 is drift, 2 is a malformed tree.

    uv run --no-sync --only-group dev python -m jup.kb_sync --jup-root ~/jup
uv run --no-sync --only-group dev python -m jup.kb_sync --jup-root ~/jup --check

  3. Commit and push ~/jup

    The pre-commit hook refuses a commit that leaves kb/ disagreeing with records/. It checks the working tree, so commit everything you edited.

    cd ~/jup && git add -A && git commit -m "..." && git push

  4. Sync into the app Erik's OK

    Needs Erik's signed-in tab open in Chrome: the app is behind IAP, so the script runs its calls inside that tab. Only added or changed files are uploaded; deleted and stale copies are removed.

    bun deploy/gcp/sync-kb.ts --check   # writes nothing
bun deploy/gcp/sync-kb.ts           # the sync

  5. If a voice file changed, re-sync the voice model Erik's OK

    The voice assistant answers from eight named files and points at them by file id. A changed file comes back under a new id, so re-point the model:

    • kb/: strategy, gas, portfolio, rued, governance, faq
    • records/projects/gas-spbg-reactivation.md
    • records/gate-assessments/gas-spbg-reactivation-g1.md
    bun deploy/gcp/sync-voice-model.ts --dry-run
bun deploy/gcp/sync-voice-model.ts

    Adding a ninth file is a governance change: it needs a date and Erik's name (ADR-0006).

  6. Sync the records bucket for the dashboard Erik's OK

    The Portfolio dashboard reads gs://jup-ops-records, a copy of ~/jup, not a live view. From deploy/gcp:

    ./sync-records.sh --check
./sync-records.sh

  7. The separate Worker assistant only if needed Erik's OK

    The public-facing strategy Worker keeps its own bundle. In ~/jup-kb-assistant-worker:

    bun build-kb-bundle.ts
wrangler deploy

  8. Verify

    • sync-kb.ts --check reports no drift.
    • Ask Asisten JUP a question only the new content answers, and check that it cites the file.
    • If a voice file changed, ask the same question in a voice call.

Route B: a staff member contributes a document

Submitting needs the group grant jup.kb.submit. Nobody has it by default, the admin role does not include it, and it must be granted exactly as true. Reviewing needs the admin role.

  1. Submit

    The staff member opens /kb-review and uploads the document with a note. It is stored as a pending file, with a SHA-256 digest of its text.

  2. Review

    An admin opens the same page, sees the queue and opens the preview.

  3. Approve or reject

    • Approve adds the file to JUP Staff Contributions; the first approval creates that collection. The file is marked approved only after the add succeeds. Approval is refused (409) if the text changed after the preview was opened.
    • Reject needs a reason. A rejected file cannot be resubmitted; the staff member uploads a corrected copy as a new file.

  4. Attach, once Erik's OK

    Approved contributions reach answers only once JUP Staff Contributions is attached to Asisten JUP's knowledge next to the Strategy KB. This is still pending (ADR-0016 step 5).

Every submit, approve and reject writes one jup.governance audit line, with ids and the result, never the document, the note or the reason. Known gap: the owner of an approved file can still edit its text; the queue then shows "changed since submitted", but it cannot stop the edit.
